# 第 10 轮 · 体验与界面发现（表格 / 空行 / 引用式链接）

侦察者：`r10-ux`。只读 `src/`、`host/`，未跑 `npm run build`，未装依赖。
代码基线：`fa06aa1`（0.22.0）。应用 `http://localhost:5173`，CDP `http://127.0.0.1:9223`（headless Edge 157）。

**方法（重要）**：dev server 是纯浏览器模式，没有宿主 `/__doc`。为了走到真实保存路径，我用 `page.addInitScript` 注入了**假宿主**：`/__doc` 返回 fixture 原文，`window.chrome.webview` 收集 `save` 消息并回 `save-result`。UI 与保存流程走的都是 `applyHostPayload` / `requestSave` 原代码，不是静态原型；差别只有侧栏仍是「打开文件夹」的空态（截图里可忽略）。
证据脚本：`.tmp/r10-ux/probe.mjs`、`probe2.mjs`、`probe3.mjs`、`probe4.mjs`、`diff.mjs`、`check-saved.mjs`；日志 `.tmp/r10-ux/probe-log.txt`。截图：`shots/round-10/`（本报告只引用 `table-*`、`source-*`、`01-*`、`06-*`）。

**结论（五条，按影响排序）**

1. **U1 源码视图只有「进来」没有「出去」：横幅按钮在源码里仍叫「在源码模式打开原文」，点它会静默覆盖源码里未保存的改动。** 这是本轮默认进源码的最大风险。
2. **U2 表格保存确认只给旧分隔行、不给新分隔行，用户无法判断「改了什么」；渲染后的表格完全一样，看不出任何变化。**
3. **U3 风险横幅把同类损失重复成长句（「2 类」其实是同 1 类 2 条），且修复后应整条消失，不该保留成「已保真」横幅。**
4. **U5 增删列后保存门失效：列数一变，表格损失不被识别，分隔行静默重写，工具条也没有任何反馈。**
5. **U4 空行损失完全静默：01 的 frontmatter 后空行消失，06 的列表间空行被插入（紧凑列表变松散列表），保存确认框不出现。**

## U1 源码模式：给「为什么」和「怎么回富文本」，并修掉横幅的静默覆盖

### 现状证据

- 含引用式链接的文档**现在不会**默认进源码：载入后 `viewMode` 仍是 `edit`（`App.tsx:326` 初值 `'edit'`；`applyHostPayload` 不调用 `setViewMode`，浏览器文档在 `App.tsx:1540` 显式设回 `edit`）。实测 `source-01-load-banner.png`：富文本 + 顶部风险横幅。
- 横幅按钮进源码后（`source-02-banner-entry.png`）：顶部横幅原样保留，按钮仍写「在源码模式打开原文」且可点；源码框没有任何「为什么在这里」的说明。`.source-hint` 只在 `dirty` 时渲染（`App.tsx:3485-3489`），刚进来时没有。
- 唯一回富文本的入口是工具栏「源码」按钮（`App.tsx:3324-3337`），它显示为**已选中**（`is-on`，截图右上角绿字），只有悬停 `title` 才是「回到编辑视图」。状态栏另有一个「源码」chip（`StatusBar.tsx:53`）。
- **静默丢改动（实测）**：源码里输入「改动会丢吗？」，`window.__slState.dirty=true`；再点横幅「在源码模式打开原文」，源码框内容回退，`dirty=false`，无确认框（`.tmp/r10-ux/probe4.mjs`，截图 `source-08-banner-click-overwrites.png`）。原因：`openSourceOriginal` 无条件 `setSourceText(rawTextRef.current)`（`App.tsx:2731-2739`）。
- 源码里改过字时的提示条文案（`source-05-dirty-hint.png`）说「点顶部『在源码模式打开原文』可恢复原文」——用户此刻**已经**在源码模式，而且点了会丢改动。

### 影响

如果本轮按简报让引用式链接文档默认进源码，每个这样的文档都会落进这个视图。用户的第一反应会是「我的排版呢」，第二反应找不到回去的按钮；一旦点了横幅按钮，刚输入的源码就没了。

### 建议改法

分两层，先修交互，再谈默认。

1. `openSourceOriginal` 增加守卫：已在源码模式时禁用/隐藏横幅按钮；`dirty` 时点击先弹确认（复用 `SaveDialog` 的取消/继续样式），文案「源码里有未保存的改动，恢复原文会丢掉它们」。
2. 源码视图常驻一条说明（不要只在 `dirty` 时显示），替换 `App.tsx:3485-3489` 的 `source-hint`：
   - 标题：`源码模式 · 文件原文`
   - 理由：`这篇有 2 条引用式链接定义。富文本编辑会在保存时删掉定义，把链接改成行内写法。`
   - 返回：把文字做成按钮 `回到富文本编辑`，右边小字 `回去后定义会在下次保存时改写`。
3. 工具栏「源码」按钮的标签随状态变：编辑态 `源码`；源码态 `回到富文本`（不再只靠 `title`）。状态栏 chip 改 `源码 · 原文`（未改）/ `源码 · 已改`（dirty）。
4. 默认策略建议：**本轮不要默认整篇进源码**。改为载入时显示选择卡（不遮正文）：`这篇用了引用式链接。` / `用源码编辑（定义不丢）` / `用富文本编辑（保存前会确认）`，并记住「这篇不再问」。理由：源码模式对长文写作是惩罚，而当前源码视图还缺上面三件事；等 U1 的交互补齐后再默认，风险才可控。若产品坚持默认，则上面 1–3 必须同轮落地，否则就是负体验。

**难度**：S–M（守卫 + 文案 S；选择卡 + 记住选择 M）。

## U2 表格：分隔行改了，用户看不出来；确认框只给旧值

### 现状证据（fixture `02-table.md`）

- 载入即出横幅（`table-01-load.png`）：
  `.risk-banner` = `这篇载入时就有会被改写的结构（1 类）：表格分隔行会被重排（列宽与对齐写法变化，单元格内容不动） | 在源码模式打开原文 | 知道了`
- 改一个单元格后 `Ctrl+S` 弹确认框（`table-03-save-confirm.png`）：
  `.save-dialog` 标题 `保存后这些写法会被改写`；`.loss-group` 只有标题、`影响 1 处` 和一行 `.loss-sample` = 旧分隔行 `|:-----|-----:|:----:|`。**没有新分隔行。**
- 点「仍然保存」后实际写回（`.tmp/r10-ux/probe-log.txt`）：
  ```
  | 项目   | 一月   | 二月   |
  | :---- | ----: | :----: |
  ```
  原 `|:-----|-----:|:----:|` 的冒号位置（左/右/居中）保住了，只改了短横数量与空格。
- 保存后横幅消失（`App.tsx:2363-2364` 清 `baselineLosses` 与 `risks`），toast `已保存到 02-table.md`（`table-04-saved.png`）。
- 渲染对比：`table-01-load.png` 与 `table-04-saved.png` 里的表格**完全一样**。用户没有任何视觉线索。

### 影响

确认框让用户「盲选」：只说会被重排，不给结果。用户会怀疑内容也变了，或者直接点「取消」放弃保存。表格是高频结构，这个摩擦每次保存都出现。

### 建议改法

1. 确认框改成前后两行（`SaveDialog.tsx:68-72` 的 `.loss-sample` 区域）：
   ```
   表格分隔行会被重排
   现在    |:-----|-----:|:----:|
   保存后  | :--- | ----: | :----: |
   只改分隔行与空格，单元格文字不动。
   ```
   数据已经存在：`Loss.before` 与 `Loss.after` 都在 `risk.ts:114-122` 里，`SaveDialog` 现在只渲染了 `before`（`SaveDialog.tsx:71`）。
2. 纯补齐列宽/空格时不要拦保存：把「只补空格」识别为等价改写（`blocking: false`），进 `SaveDialog.tsx:75-84` 的「等价改写」区。理由：本轮目标 1 修好后这类差异本来就不该出现；若序列化仍要动，就不值得打断用户。
3. **不要加「保留原格式」开关**。表格分隔行没有需要用户选择的语义，保留应是自动行为。加开关只会让用户以为格式有风险。
4. 文案区分「对齐是否变化」：对齐变了才用「改写」，只补空格用「规范化」。

**难度**：S（对话框渲染 before/after + 分类），M（若要把「只补空格」判成等价改写，需要按 `after` 逐格比较对齐符）。

## U3 风险横幅：修好后整条消失；分类文案按「已拦截 / 已保真」拆开

### 现状证据

- 02 横幅（1 类）与 04 横幅（2 类）都常驻在正文上方（`table-01-load.png`、`source-01-load-banner.png`）。
- 04 的 `.risk-banner` 文本：
  `这篇载入时就有会被改写的结构（2 类）：引用式链接定义 [tiptap]: … 会被丢掉，正文里的链接会被改写成行内形式；引用式链接定义 [cm]: … 会被丢掉，正文里的链接会被改写成行内形式`
  两条几乎逐字重复，没有条数，用户要读两遍才知道是「2 条同一种问题」。
- 「2 类」来自 `risk.length`（`App.tsx:3469-3472`），而 `risk` 是 `lossLabels()` 去重后的**标签数组**（`App.tsx:804`、`risk.ts:311-319`）。标签里带 `[id]`，所以同类不同 id 不会合并。
- 点「知道了」只是 `setRisks([])`（`App.tsx:3477`），内存态；重新载入同一篇会再出现。源码模式下横幅仍在（`source-02-banner-entry.png`），按钮名与当前状态矛盾。

### 影响

修复 02/04 后，这条横幅的存在感会变成噪音：一篇正常表格文档每次都提醒「会被改写」，用户学会无视它，真正需要拦截时也会被无视。反过来，如果保留成「已保真」横幅，等于给所有正常文档加一条无动作的常驻条。

### 建议改法

1. **02/04 修好后横幅整条消失**，不保留「已保真」版本。理由：横幅的唯一价值是提供动作（看原文 / 仍然保存）；没有拦截就没有动作，只剩噪音。
2. 需要正向信号时，用**保存成功 toast 追加**：`已保存到 02-table.md · 原格式保留`。这条只在保存时出现一次，不占正文顶部。
3. 仍存在混合损失时（部分保真、部分拦截），横幅只列**拦截项**，并按 kind 合并计数：
   ```
   保存会改写 2 处：引用式链接定义 2 条。
   正文里的链接会变成行内写法，定义块会删除。
   [查看改动] [在源码模式打开] [知道了]
   ```
   「已保真」项不出现在横幅里，只在确认框的「等价改写」区或保存 toast 里出现。
4. 文案分两套标签与色调：拦截 `--mark`（橙，现 `.risk-banner` 样式 `styles.css:1524-1554`）；已保真用中性 `--ink-faint`，并且只在 toast 里出现。
5. 横幅在源码模式下隐藏，换成 U1 的 `源码模式 · 文件原文` 说明条；按钮改为 `回到富文本编辑`，不再显示「在源码模式打开原文」。

**难度**：S（隐藏 + 合并计数 + 两套文案）。「记住知道了」若要跨载入持久化，另算 M（需要按文档键存 localStorage 或 `.sidelight`）。

## U5 表格工具条：加/删列后保存门失效，界面没有任何提示

### 现状证据

- 工具条出现条件 `editor?.isActive('table')`（`App.tsx:3364`），7 个按钮：上插入 / 下插入 / 左插入 / 右插入 / 删行 / 删列 / 删表（`App.tsx:3367-3387`），无任何状态文案。实测可见（`table-02-toolbar.png`）。
- 点「右插入」后再保存：**没有确认框**（`.tmp/r10-ux/probe-log.txt`「[A2 加一列] 保存确认框: (未出现)」），直接写回：
  ```
  | 项目  |     | 一月   | 二月   |
  | :--- | --- | ----: | :----: |
  ```
  截图 `table-06-add-column-saved.png`（与加列后界面相同，无提示）。
- 原因：表格损失的 key 是表头单元格拼起来的（`risk.ts:100-104`），加列后表头变了，`after.get(key)` 取不到，`risk.ts:112` 直接 `continue`（注释还写着「用户改了表头，不算结构损失」）。于是「最需要重写分隔行」的操作反而绕过了保存门。
- 删列同理：key 变，绕过。
- 行操作不改变分隔行，不受影响。

### 影响

用户加了一列，保存后文件里的分隔行与所有行的空格都被重排，没有任何说明。若用户对 diff 敏感（Git 仓库里的文稿），会看到整张表被改写，却不知道是哪一步造成的。

### 建议改法

1. 规则：**行操作静默**；**列数变化才提示**，且只在列数真的变了（不是每次点按钮）时。
2. 提示放两处，二选一即可：
   - 表格工具条右侧加一行灰字：`4 列 · 保存时按新列数重写分隔行`（列数与原始不同时出现）。
   - 保存成功 toast：`已保存到 x.md · 表格按 4 列重写分隔行（对齐保留）`。
   推荐后者：不改工具条布局，提示只出现一次，与 U3 的 toast 方案一致。
3. 对齐策略写清楚：保留原有列的 `:`，新列默认左对齐（`:---`）。不要为「新列对齐」加弹窗；本轮不做对齐编辑。
4. 如果列数变化后连原对齐都保不住，文案改成 `表格对齐已按当前列重排`，并允许从 toast 打开源码查看（`Notice.action` 已支持，`App.tsx:180`）。

**难度**：S（toast/工具条文案），M（如果要让保存门在列数变化时仍能给出「哪些列被重排」的明细）。

## U4 空行：现在完全静默；建议保留，修不了就进 toast，不进拦截

### 现状证据（实测保存写回，`.tmp/r10-ux/saved-*.md`）

- `01-obsidian-note.md`：保存后 **frontmatter 后的空行消失**（原文第 6 行 → 写回第 5 行后直接 `# 周记`），同时在文件末尾多出一个空行，总空行数 5→5 掩盖了位置变化。保存**没有确认框**，也没有任何提示（`01-02-saved.png`）。
- `06-task-list.md`：保存后在任务列表与 `- 普通条目` 之间**插入**一个空行（第 5 行），空行数 5→6；同样没有确认框。Markdown 语义上这会把紧凑列表变成松散列表（`<li>` 里包 `<p>`，GitHub/Obsidian 行距变大）。
- 原因：空行损失 `blocking: false`（`risk.ts:278-289`），基线只收 `blocking` 的（`risk.ts:295-297`），`activeLosses` 也只返回 `blocking`（`risk.ts:303-309`）。所以它永远进不了 `SaveDialog`；`SaveDialog` 只在有拦截项时才打开（`App.tsx:1884-1889`）。
- 自动保存遇到拦截项只置「需手动保存」（`App.tsx:2161-2167`），空行不触发，所以连状态栏都看不到。

### 影响

空行不改正文，但对两类人要紧：用 Git 管文稿的人看到无意义 diff；跨渲染器发布的人看到列表疏密变了。当前实现是「静默改」，与本轮「不许静默」的目标直接冲突。

### 建议改法

1. 首选：在序列化层保住 01 的 frontmatter 后空行与 06 的列表间空行（本轮目标 2）。保住了就什么都不用加。
2. 保不住时的兜底，按代价从低到高：
   - **保存成功 toast 追加**：`已保存到 x.md · 空行调整 2 处`（只在 >0 时出现）。不打断，不弹窗，`Notice` 已支持持久与动作。
   - `SaveDialog` 的「等价改写」区补一行：`空行调整 2 处（不拦保存，列表疏密可能变化）`，但只在对话框因其它原因打开时顺带显示。
3. **不要空行单独弹确认框，也不要单独弹 toast 标题**。理由：没有内容丢失，打断成本高于收益；用户连续保存会被反复打断。
4. 若只允许一件事：做 2 里的第一项（toast 追加），它同时覆盖 01 与 06，且实现只需在保存成功处比较 `blank-lines` 的 count。

**难度**：S（toast 追加），M（序列化保真，属于本轮实现任务）。

## 界面代码优化机会（最多 3 条）

1. **「正文 + frontmatter + 脚注」的拼装重复 4 次**：`App.tsx:800-803`（宿主载入基线）、`1499-1504`（切文档基线）、`1508-1511`（撤销基线）、`1780-1785`（`currentMarkdown`，保存时用）。四处都是 `joinFrontmatter(…, joinFootnotes(serializeBody(editor), …))` 的变体，任何一处漏改就会出现「基线算的和写回的不是同一份」。建议抽 `currentFullText(editor): string`，基线与保存共用。难度 S。
2. **风险文案的「分类」在三处各算一遍**：`lossLabels`（`risk.ts:311`）把 `Loss[]` 压成字符串，横幅（`App.tsx:3469-3472`）丢失 kind 与 count；确认框（`SaveDialog.tsx:18-39`）自己 `groupsOf` 再分组；自动保存（`App.tsx:2161-2167`）只看 `length`。建议在 `risk.ts` 导出 `riskSummary(losses): { blocking: Group[]; equivalent: Group[] }`，三处共用，U3 的「同类合并计数」和 U2 的 before/after 都从这里取。难度 S。
3. **横幅样式与工具条按钮重复**：`.readonly-banner`（`styles.css:1496-1522`）与 `.risk-banner`（`1524-1554`）是同一套 sticky/居中/间距/按钮样式的两份拷贝；表格工具条 7 个按钮（`App.tsx:3367-3387`）都是 `run((chain) => chain.xxx())` 的重复。建议抽 `.doc-banner` 基础类 + 两个 tone 修饰类；工具条用 `[['上插入', c => c.addRowBefore()], …].map` 生成，顺带给每个按钮补 `title`（现在只有文字，悬停没有解释）。难度 S。
