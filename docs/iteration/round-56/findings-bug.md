## F1（P1，已记 B-119）行内语法开启后，连续符号段与空格旁的 `~`/`^` 被当成定界符，Ctrl+S 静默改写正文

复现：设置勾「快捷行内语法」→ 拖入 `==== 与 ==不闭合` → 屏幕上显示 `==` +「与」高亮 + `不闭合`；`Ctrl+S` 落盘为 `== ==与== 不闭合`。重开这篇时字面 `==不闭合` 已变成 `不闭合`（`==` 被当成收尾定界符吃掉了）。

开关两态对照（同一 `showSaveFilePicker` stub，捕获应用真实写盘串；`.tmp/r56-finder-d.log`，关态 6/6 逐字节同、开态 6/6 全变）：

| 输入（+`\n`） | 开态写盘 |
| :--- | :--- |
| `==== 与 ==不闭合` | `== ==与== 不闭合` |
| `x ==== y ==z` | `x == ==y== z` |
| `^^ 与 ^不闭合` | `^ ^与^ 不闭合` |
| `a ^ b 与 c^d` | `a  ^b 与 c^d` |
| `~a~ ~b~ 与 a ~ b 与 H~2~O` | `~a~ ~b~ 与 a  ~b 与 H~2~O` |
| `== a ==` | ` ==a== ` |

- 解析证据：DOM 为 `==<span class="sl-eq"> 与 </span>不闭合`（`.tmp/r56-finder-b.log`）；截图 `shots/round-56/inline-run-bug.png`（两行同时错：`~` 跨词成下标、`====` 吞后文 `==`）。
- 期望：`====`、`^^` 这类连续符号与空格分隔的单侧符号按字面保留；`src/components/SettingsDialog.tsx:119` 也承诺「写回字节两种状态都一样」。
- 实际：`src/lib/inlineSyntax.ts:35-37` 的 `whole` 只在定界符后看 1 个字符（`(?!=)` / `(?!~)`），没有 CommonMark 的左/右 flanking 与「连续符号从第二半重试」规则；`:77-86` 的 tokenizer 逐候选位重试，`====` 的第二对 `=` 因此能开段、并把后文 `==不闭合` 的 `==` 当收尾。`a ~ b` 的 `~` 同理（开定界符后是空格本应拒绝）。
- 建议：三处 `whole` 加 flanking 守卫（开/收尾定界符左右不得同符号、开定界符后不得空白、收尾前不得空白），或在 tokenizer 里按「候选位前后各 1 字符 + 连续符号长度」判定；补单测：`==== 与 ==不闭合`、`^^ 与 ^不闭合`、`a ^ b 与 c^d`、`a ~ b 与 H~2~O`、`== a ==`。修前先把设置提示的「字节一样」改成实际行为。
- 定级说明：默认关、无崩溃，故记 P1；但保存后磁盘正文的文字与符号确实变了，若按「保存静默改字 = 数据丢失」口径应升 P0。
