# 第 01 轮简报

## 本轮目标

用证据建立真实基线，找出会挡住「可发布」的前 5 个问题，并给发布路径决策准备事实。本轮不做大重构。

## 三个视角

- **缺陷**：数据丢失优先。`npm run shot` 已出现货币写法 `$5 到 $10` 被当成公式吞字的迹象，先确认。再看保存、切换文档、批注恢复、往返损失。
- **体验**：第一次使用的中文写作者能否 30 秒内开始写作；工具栏、设置、状态栏、查找、页边批注、错误反馈、键盘流、窄窗口。
- **发布**：开源就绪度、体积构成、冷启动、Windows 安装路径（无管理员权限）、图标与应用标识。
- **优化机会**：三个视角都要顺带指出代码层面的优化点：重复逻辑、死代码、过大的单文件、渲染热点、可延后加载的体积。优化建议要写清收益与风险，不为了改而改。

## 边界

- finder 只读，不改 `src/`、不改 `scripts/`。唯一可写：`docs/iteration/round-01/findings-*.md` 与 `shots/round-01/`。
- 不装新依赖，不重启 dev server，不删除文件。
- 端口：app `http://127.0.0.1:5173`；CDP 浏览器 9222 / 9223 / 9224 各归一个 finder，别抢。
- 结论必须有证据：命令输出、截图路径、`文件:行`。没验证的标「未验证」。

## 交付

三份发现，每条带编号、影响、建议方向、难度（S/M/L）。planner 会按编号写计划，所以编号要稳定。
