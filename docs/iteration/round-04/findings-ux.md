## 2. U1 保存没有落点：静默下载、文件名固定、提示不指路、示例没有「原文件」（难度 M）

**实测（`.tmp/r4-ux-final.json`）**

| 检查 | 结果 |
| --- | --- |
| 下载文件名 | `示例 · 未命名.md`（顶栏名 = 文件名，用户不能改：`doc-name` 是 `div`） |
| 下载内容 | 598 B，含新写的一句 → 下载本身成功 |
| 提示条文字 | 「这篇还没有磁盘路径。副本已下载到「下载」文件夹；要写回原文件，先用「打开文件夹」打开它所在目录。」（609 px 宽，底部居中） |
| 提示条角色 | `role="status"`（非 `alert`）、无关闭按钮、无动作按钮 |
| 提示条寿命 | 6,106 ms 后消失（`src/App.tsx:882-884` 固定 6000） |
| 保存前后 | 绿点保持（正确语义），但页面没有一句话解释「为什么还没保存」 |
| 打开文件夹后保存 | 仍下载副本，不写进刚打开的文件夹（正文还是示例、树里无选中项）（`.tmp/r4-ux-extra.json` → `folderOpened`） |
| 「另存为」 | 全仓库无 `showSaveFilePicker` 调用（`grep` 0 处），保存落点不可选 |

**为什么这是第一次使用最大的坑**

1. 提示说「要写回原文件」——示例文档**没有原文件**。这句话把用户送去「打开文件夹」找一个不存在的文件。
2. 提示不写文件名，也不给「打开下载文件夹」。用户关掉提示后只能自己去资源管理器翻。
3. 顶栏显示 `示例 · 未命名.md`，与下载文件名相同，但界面上没有任何「已保存副本：…」的状态。绿点仍在，用户会以为保存失败。
4. 打开文件夹之后保存仍下载，与「我有文件夹了」的预期相反。
5. 宿主（`host/`）里没有任何 `DownloadStarting` 处理（`grep` 0 处）。安装版里同样的「保存」是否下载、下载到哪，本轮**未验证**；不接这个事件时 WebView2 可能直接取消下载，用户会看到点击后毫无反应。

**改法**

1. 保存前问落点：没有句柄时调 `showSaveFilePicker`（`suggestedName` 用当前文档名去掉「示例 · 」）；宿主里接保存对话框。用户取消就什么也不做。
2. 没接对话框之前，至少把提示改成三句并给按钮：
   「已下载副本：**下载 / 示例 · 未命名.md**。」「要写回原文件，用「打开文件夹」打开它所在的目录。」按钮「打开下载文件夹」（宿主）或「知道了」。提示条改成 `role="status"` + 手动关闭，不自动消失。
3. 顶栏文档名旁加持久状态：`未保存` / `副本在「下载」` / `已保存 14:32`。绿点单独一个 5px 点太轻。
4. 文案里不要出现「磁盘路径」「磁盘句柄」（见 U3）。

**难度 M**（文案与提示条 S；保存对话框 M，需产品负责人确认能力）。

## 3. U2 三种状态都没有「新建」，也没有「另存为」（难度 M）

**实测（`.tmp/r4-ux-extra.json` → `newEntryProbe`）**

| 状态 | 用户想「新建」会怎么做 | 界面上有什么 | 缺什么 |
| --- | --- | --- | --- |
| 没文件夹（首屏） | 找「新建」→ 没有；只能删光示例正文，名字仍是 `示例 · 未命名.md` | 文件树 3 个按钮：打开文件夹 / 打开文件 / 试用示例（`FileTree.tsx:119-128`） | 新建、改名、另存为 |
| 有文件夹（伪 `我的写作`） | 看文件树 → 头里只有一个 `‹` 折叠按钮（`FileTree.tsx:138-145`）；顶栏 5 个按钮也没有 | 树头写 `我的写作`，两项文件 | 树头「＋ 新建文件」、右键菜单、`Ctrl+N` |
| 示例（`示例文集`） | 同上；示例是只读的（`handle: null`），保存只能下载 | 5 项文件，文档名 `开始写.md` | 「新建到示例里」不该给，但界面不说明示例只读 |

- 全页（三态）按钮文本里都没有 `新建 / 新文档 / 另存为`：`bodyTextHasNew = false`，`allButtons` 22 项无匹配（`.tmp/r4-ux-extra.json`）。
- `Ctrl+N` 无反应：文档名与正文都不变（`ctrlN`）。`src/App.tsx:1181-1263` 的 `onKeyDown` 只处理 Escape、`Control+Shift+P`、`Control+S`、`Control+F/H`、`Control+= / − / 0`（字号），没有 `n`；Ctrl+Enter 在 Tiptap 扩展里。
- 文档名不可编辑（`src/App.tsx:1695-1698` 是 `div`），所以「改名」这条退路也没有。

**「另存为」该放哪**

| 位置 | 理由 | 建议 |
| --- | --- | --- |
| 顶栏「保存」右侧的 `⋯` / 「文件」菜单 | 全局动作，三种状态都成立；用户已在顶栏找保存 | **首选**。「新建」「另存为…」「打开…」「打开文件夹…」四项 |
| 文件树头 | 只在有文件夹时有意义（要 `rootHandle.getFileHandle(name,{create:true})`） | 有文件夹时加「＋ 新建文件」；示例态不显示 |
| 「导出 ▾」菜单 | 导出是另一种事（HTML / 纯文本 / PDF），混进去会更乱 | 不放 |

**改法**

1. 新增 `src/components/FileMenu.tsx`（按钮 + 现有 `.menu` 样式），顶栏放一个「文件 ▾」，含四项。全部只走已有 FSA 路径（`pickWorkspace`、`pickFile`）加一个 `showSaveFilePicker`。
2. 无文件夹时「新建」= 清空成一篇空文档，名字 `未命名.md`，`dirty = true`；「保存」就等于「另存为」，先选落点。
3. 有文件夹时「新建」= 在树里插一个 `未命名.md`，立刻获得写句柄，`Ctrl+S` 直接写盘。
4. 给示例态 `workspace.demo === true`（`workspace.ts:324` 已有字段）加树头徽标「示例 · 改动不写盘」。

**难度 M**（菜单与状态机约 80–120 行；FSA 分支已存在）。

## 5. U4 键盘：Tab 21 次到正文，键位无提示，`aria-keyshortcuts` 为 0（难度 S）

**实测（`.tmp/r4-ux-extra.json`）**

- 焦点顺序（26 次 Tab，第 21 次进正文）：分析本段（模拟）→ 导出 ▾ → 保存 → 设置 → 插入 ▾ → H1 → H2 → B → I → S → `</>` → 专注 → 打字机 → 源码 → 预览 → 文件 → 大纲 → 打开文件夹 → 打开文件 → 试用示例 → **正文**。
- `a[href^="#"]` = 0（无 skip link），`aria-keyshortcuts` = 0，`a` 总数 = 0。
- 带 `Ctrl` 的 `title` 只有 1 个：「预览 → 只读预览（Ctrl+Shift+P）」。
- 保存、设置、导出、插入、批注：`title` 全是 `null`。
- 地标只有 `HEADER.topbar`、`ASIDE.file-tree`、`ASIDE.margin-rail`；无 `main`，正文是 `DIV.tiptap[textbox] tabindex=0`。
- 焦点环正常：`2px solid rgb(43,109,100)`、offset 2px（`styles.css:96-99`），深色下同样可见。
- 完整键位表只出现在示例正文《快捷键》一节；用户清掉示例就没了。

**改法**

1. `.app` 第一个子元素加 `<a class="skip-link" href="#editor">跳到正文</a>`，`:focus` 时左上角显示；给 `.tiptap` 加 `id="editor"`（它已有 `tabindex=0`）。
2. 键位表从 `if` 链抽成常量：`[{ id:'save', keys:'Control+S', title:'保存（Ctrl+S）' }, …]`，`onKeyDown` 与按钮属性同源；给保存、新建、导出、插入、批注、分析补 `title` 与 `aria-keyshortcuts`。
3. 顶栏末位加「?」按钮，点开一张键位表（复用 `.menu` / `.dialog` 样式，不引依赖）。
4. 工具条 B / I / S / `</>` 的 `title` 补键位（Tiptap 默认 Control+B / I / Shift+S / E）。

**难度 S。**

## 7. 界面代码优化机会（最多 3 条）

### C1 文档名既不可改、又被四处当文件名用（难度 S）

- `src/App.tsx:255` 的 `docName` 是唯一来源，但只会从 `initial.name` 或 `loadIntoEditor` 赋值；顶栏是只读 `div`（`:1695-1698`）。
- 它同时决定：下载文件名（`:1126`）、保存提示里的「原文件」（`:1130-1133`）、三种导出名（`:1386`、`:1393`、`:1404`）。
- 加一个 `renameDoc(name)`（顶栏做成可双击编辑或菜单项），四处自动受益；U1 的「副本永远叫 示例 · 未命名.md」随之消失。净增约 15 行，删掉未来每处特判。

### C2 顶栏与文件树各自硬编码动作，没有共用的「文件动作」层（难度 S/M）

- 顶栏 5 个按钮（`:1690-1760`；其中「批注」只在 ≤1119px 显示）、文件树空状态 3 个按钮（`FileTree.tsx:119-128`）、树头 1 个折叠按钮（`:138-145`）是三个平行清单，`onOpenFolder` / `onOpenSingleFile` / `onOpenDemo` 从 `App.tsx:1964-1975` 逐个往下传。
- 抽 `FileMenu`（新建 / 打开文件 / 打开文件夹 / 另存为 / 试用示例）一处渲染，顶栏与文件树都吃它；U2 的新入口只写一遍，`FileTree` 的 props 从 6 个减到 3 个。

### C3 键位信息散在 `onKeyDown` 的 `if` 链里（难度 S）

- `src/App.tsx:1181-1263` 的 8 个 `if` 是唯一键位真相，按钮的 `title` / `aria-keyshortcuts` 全为 0，第三轮和本轮都要逐个比对。
- 抽 `const SHORTCUTS = [{ keys:'Control+S', label:'保存', run: saveFile }, …]` 一张表，`onKeyDown` 遍历它，按钮从同一张表读 `title` 与 `aria-keyshortcuts`。U4 一次修完，下次加键位不再漏文案。
