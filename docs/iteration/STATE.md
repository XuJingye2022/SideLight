# Sidelight 迭代看板

这份文件是所有参与迭代的代理的共享记忆。每轮结束由根代理更新。

## 目标

把 Sidelight 做成可发布的开源桌面 Markdown 编辑器，Windows 首发。验收维度：功能好用、安装简单、体积小巧、界面简洁美观、易于操作。

## 循环 v3（两轮一侦察，不设轮次上限）

停止条件：任意一轮 5 路侦察合计 0 个新 P0/P1，且 `BACKLOG.md` 没有 open 的 P0/P1；P2 不阻塞。不设总轮次预算。发现池在 `docs/iteration/BACKLOG.md`，P2 可以之后一点点完善。

每个两轮周期：

1. **侦察**：5 个 finder 并行（缺陷 / Typora / 安装启动 / 代码性能 / 界面），各 15 分钟、≤4 条，写 `BACKLOG.md` 与 `round-NN/findings-*.md`（≤4 KB）。
2. **计划**：planner 写两轮计划（每轮 ≤3 任务，≤6 KB）；critic 只审 P0/P1 与高风险，最多 1 次修订。
3. **实施 + 验收**：第 1 轮 executor（25 分钟）→ tester（15 分钟）；第 2 轮先 1 个 finder-delta 做 10 分钟回归检查，再 executor → tester。
4. **批末**：scribe 同步 README/AGENTS/CHANGELOG/STATE/METRICS。

每轮 tester 独立验收并 commit；FAIL 修复 1 次，仍 FAIL 回滚。根代理只在批次之间复核门禁与指标。

## 门禁

- `npm run build`（类型检查 + 打包）
- `npm run verify`（build + 首屏 gzip 字节门；改过 `src/` 就要跑）
- `npm test`（以 `package.json` 为准，当前 54 个文件 724 条）
- 改编辑器或 Markdown 序列化时加跑 `npm run roundtrip`
- 界面变化必须截图到 `shots/round-NN/`，实施报告里引用
- 每轮 PASS 后 tester 串行跑门禁并 commit：`round-NN: <一句话>`；根代理每批复核一次

## 产品硬约束（动手前读 AGENTS.md 与 docs/adr/）

- 编辑器内核 Tiptap，不换。
- AI 不直接写正文：修订建议只有人点「采纳」才落入正文。
- 意见用页边批注，不退回右侧列表。
- 只做自带密钥，不代管请求。
- 缓存只写 `.sidelight/`，文档同级优先，打开文件夹时写工作区根目录。
- 不新增运行时依赖，除非省下的代码比依赖大；加了要在 README 记一行理由。
- 轻量仍是体验指标：不加后台常驻、启动不联网；同功能取最小实现。优先级：**稳定性 > 核心功能 > 体积优化 > 节省 Token > 工作速度**。安装包硬线 **50,000,000 B**（内部 **45,000,000 B**），首屏 gzip 内部 **310,000 B** / 硬线 **320,000 B**；不要为了省几 KB 砍能提升体验的功能。
- 术语以 `GLOSSARY.md` 为准，术语变了当场改。
