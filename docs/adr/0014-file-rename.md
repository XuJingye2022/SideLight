# 文件重命名：同目录、只改后缀名、`move()` 唯一路径

文件树已经有删除（ADR-0013）。用户下一个自然需求是改文件名——打完草稿发现标题写错，只能去资源管理器。

重命名的风险比删除低（不丢内容），但会破坏三类引用：当前文档路径、`.sidelight` 缓存键、最近记录。本轮只做最小闭环。

## 决定

- **同目录**：只在当前目录内改名，不跨目录移动。跨目录要处理目录引用、批注锚点与工作区边界，属于独立改动。
- **只接受 `.md` / `.markdown`**：其它扩展名拒绝（`BAD_REQUEST`）；不自动补 `.md`，不改变大小写规则以外的文件名。
- **目标存在就拒绝**：先检查一次，再用 `File.Move` 的「目标已存在即抛」语义做二次探测；两次之间仍有 TOCTOU 窗口，二次探测只收窄、不消除，错误信息写清「目标已存在」。
- **`move()` 是唯一路径**：不做「复制 + 删除」回退——复制会短暂出现两份内容，失败时更难判断哪份是真相。`File.Move` 在同卷是原子改名；跨卷（同目录内不会发生）不支持。
- **大小写重命名**（`a.md` → `A.md`，Windows 不区分大小写）：分两段做——先改成临时名 `<guid>.tmp`，再改成目标大小写；第二段失败时**保留临时名**并报错，不尝试回滚成原名（回滚也可能失败，且会覆盖用户看到的现状）。错误文案说明「文件现在是 <临时名>」。
- **缓存迁移**：`.sidelight/drafts/<旧 key>.md` 与 `.sidelight/annotations/<旧 key>.json` 写到**新 key** 成功后才删旧 key；写失败保留旧文件并报错，绝不先删。
- **最近记录不迁移**：`recent.json` 里的旧路径不改写（宿主没有跨进程文件监视，改记录会与「刷新重绑」口径冲突）；旧条目下次打开回 `FILE_GONE`，用户可移除。
- **目录不做**：目录重命名会牵动树结构、当前文档路径与所有子文件缓存，本轮明确不做。

## 边界

- 改名后当前文档的 `currentPath` 指向新路径；随后的 `Ctrl+S` 写新路径（宿主写回通道用 `currentPath`，不需要前端拿路径）。
- 改名不改变文件内容、编码、BOM 与换行；不触发保存门。
- 只读目录、被占用文件、网络盘失败给可见错误，原文件保持原名。
- 目标名与原名只差大小写时走两段式；两段式失败保留临时名，属于已知取舍。
- 改名不清 `recent.json` 条目，也不改 trash 里的历史记录。

## 否决的方案

- **复制 + 删除回退**：短暂双份内容，失败时语义不清；`File.Move` 足够。
- **跨目录移动**：与改名混在一起会让「同目录」的简单语义变复杂，本轮不做。
- **自动补 `.md`**：用户输入什么就是什么；补后缀会让「目标存在」判断与用户预期不一致。
- **迁移最近记录**：要写 `recent.json` 并重新排序，且与刷新重绑冲突；旧条目失效可接受。
- **先删旧缓存再写新**：崩在中间会丢草稿/批注。

## 验收与未验

- 自动验证：同目录改名成功、目标存在拒绝、非 `.md` 拒绝、大小写两段式、缓存新键写入成功才删旧键、旧最近条目 `FILE_GONE`、改名后 `Ctrl+S` 写新路径。
- UNVERIFIED：真人右键重命名与确认框、Windows 资源管理器同时打开旧文件、网络盘/OneDrive 占位文件、超长路径与中文名、并发改名同一文件、两段式失败后的临时名恢复。
