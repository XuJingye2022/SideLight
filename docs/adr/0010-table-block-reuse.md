# 表格整块复用：只对没动过的表格承诺原样写回

Markdown 表格在编辑器里会丢信息：分隔行的对齐写法、列宽空格、单元格内多余空格、表格前后的空行。旧实现每次保存都把表格按编辑器规范重排，roundtrip 的 02-table 样本因此有 5 行变化，并被保存门拦下。

本轮改为「载入时记住原文块，保存时原样写回」——但只对**没动过**的表格成立。

## 决定

1. 载入时给每个表格记一份原文块（从表头上一行到表格最后一行的原始字节）与签名。
2. 签名 = 表头单元格文本 + 每行单元格文本 + 列数（不看向齐标记、列宽空格、单元格内空格）。
3. 保存时若当前表格签名与原文一致，**整块写回原文**；不一致就走正常序列化。
4. 三种退让（都不弹保存确认）：
   - 改过单元格值 → 重新排版；
   - 增删行列 → 重新排版；
   - 改对齐标记 → 重新排版。
5. 只承诺「没改动过的表格不会被改」，**不承诺「表格永远保真」**。

## 边界

- **行内字节**：单元格内空格、对齐标记、列宽空格按原文写回；表格前后的空行只保留**一个**。
- **前后 ≥2 空行**：会被规范化成一个空行（原文块的起止点按相邻块边界算，多余空行属于块间空白）。
- **改过的表格不进保存门**：载入基线里已没有表格损失，所以改单元格后再保存不会弹确认。这是已知取舍：用户改过的表格按编辑器规范排版，差异不拦。
- 表格嵌套、HTML 表格、表格内的块级元素不承诺。

## 测量

三栏口径见 `docs/roundtrip-report.md` 的汇总与逐样本表：富文本 **5 / 7** 完全保真（02-table 从「被拦截」变成完全保真）；源码路径 **7 / 7** 等值（按定义、未编辑）；富文本首次保存仍拦截 **1 / 7**（04 引用式链接）。三栏不能相加。

## 与 ADR-0001 的关系

ADR-0001 说「文档树是真相」。本条**收窄**它，不推翻：文档树仍是编辑与保存的真相，只有「签名未变的表格」允许用原文块覆盖序列化结果。这是字节级保真的一个例外，必须同时满足签名一致与未编辑。

## 未决

- 表格前后空行的规范化阈值（≥2 归 1）是否该按文件级设置可关。
- 签名是否要包含单元格内的行内标记（加粗、链接）——目前只比文本，标记变化可能被原文块覆盖。
- 大表格（数千行）记原文块的内存与载入耗时未测。

## UNVERIFIED

- 真实宿主（`/__doc` + `postMessage`）保存表格的字节：本轮只有浏览器路径与 roundtrip 脚本。
- 中文全角空格与制表符混排的表格。
- 与批注锚点叠加时，原文块写回是否影响锚点位置。
