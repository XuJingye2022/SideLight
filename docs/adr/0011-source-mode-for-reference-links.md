# 含引用式链接定义的文档：载入后默认进源码模式

引用式链接（`[id]: https://…` 定义块）在富文本往返里必然丢定义：Tiptap 只认行内链接，序列化后定义块消失，正文引用变成纯文本。旧实现把它当「保存门要拦的差异」——用户每次保存都要确认一次，改完还是丢定义。

本轮改为：载入时检测到定义行，直接进源码模式，保住原文；切回富文本后首次保存仍拦一次。

## 决定

- **触发条件**：只在载入时检查；只认定义行（行首 `[id]:` 后跟 URL，允许 `<>` 包裹）；草稿恢复、新建、示例文档不走这条。
- 命中即调用 `enterSourceFor(text)`：
  - 同时 seed `sourceText` 与 `sourceBaselineRef`（两者必须同源，否则 dirty 判定会错）；
  - 顶部提示说明「这篇文档用了引用式链接定义，已切到源码模式」；
  - 不写盘、不改文件。
- **退出与 dirty 守卫**：
  - 用户点「预览」切回富文本时，`sourceBaselineRef` 仍是源码文本；富文本一旦被编辑，dirty 照常；
  - 切回富文本不丢失源码文本，再切回源码仍是原文；
  - 保存走当前视图：源码保存写 `sourceText`（原文），富文本保存走正常序列化 + 保存门。
- **富文本首次保存仍拦一次**：定义块属于 `blocking` 差异；确认一次后不再重复拦（同一篇）。

## 为什么不用「自动改写定义」或「静默丢定义」

- 自动改写要重写定义块与所有引用，等于替用户改文件，风险高于收益。
- 静默丢定义违反「不静默改写」底线。
- 默认源码模式是最小改动：不碰文件，用户想用富文本仍可切回。
