# 文件树只做删除：用 trash 语义保底，不提供应用内恢复

文件树现在只能打开与新建。用户想删掉一篇写废的稿子，只能去资源管理器。把删除做进应用后，风险不是「删不掉」，而是「删错没法回头」：没有回收站语义的 `Delete` 会永久丢稿。

本轮只做「删除文件」：移到工作区自己的 trash 目录，不提供应用内恢复，不自动清理。

## 决定

- **只删文件，不删目录**：目录删除要递归、要确认树结构、要处理正在编辑的文档，风险与收益都不成比例；本轮明确不做。
- **只做删除；重命名见 [ADR-0014](0014-file-rename.md)**：同目录改名单独一轮做；移动/复制仍不做——它们要处理重名、跨目录引用、批注与草稿的 key 重算。
- **trash 语义**：删除 = 把文件移到 `<工作区>/.sidelight/trash/<时间戳>-<原文件名>`：
  - 时间戳用 `yyyyMMdd-HHmmss`，同一秒内重名时追加 4 位随机后缀（`-a1b2`）；
  - 目标路径不覆盖已有文件：先尝试 `<时间戳>-<名字>`，已存在就加随机后缀；
  - 移动用 `File.Move`；跨卷或移动失败时回退为「复制 + SHA-256 校验 + 删除源文件」，校验不一致就保留源文件并报错；
  - 移动成功后文件树刷新、当前文档若被删则提示并清空编辑区。
- **不提供应用内恢复**：trash 只是「不立刻永久删」的保底；恢复靠用户在资源管理器里把文件挪回去。应用内恢复要索引、要冲突处理、要 UI，本轮不做。
- **不自动清理**：trash 只增不减，用户自己清；卸载也不删（它可能在用户文档目录里）。
- **不监听目录**：外部改动靠「刷新」重绑；刷新时重新扫描工作区、重建文件树、保持当前文档高亮（按规范化路径匹配），不丢草稿与批注。
- 删除前必须确认（文件名 + 「移到 trash，不自动清理」）；只对文件生效，右键菜单里目录不出现删除项。

## 边界

- trash 目录在**工作区**内（`.sidelight/trash/`），不是系统回收站；不写 `%TEMP%`。
- 同一文件反复删除会产生多条 trash 记录（时间戳不同），不合并。
- 只读文件、被占用的文件、网络盘删除失败时给可见错误，文件保持原位。
- 卸载安装包不删 `<工作区>/.sidelight/`（含 trash、草稿、批注）。
- 删除不会清 `recent.json` 里的记录；下次从最近列表打开会得到 `FILE_GONE`。

## 否决的方案

- **直接 `File.Delete`**：违反「不静默毁数据」底线，删错无法回头。
- **系统回收站（SHFileOperation）**：需要 COM 与 UI 线程，跨卷行为不一致；工作区内 trash 更可解释、可测试。
- **应用内恢复 UI**：要索引、冲突处理、批量恢复，本轮范围外。
- **自动清理（如 30 天）**：用户没同意就不该删；本轮明确不清理。
- **监听 `FileSystemWatcher`**：事件风暴、跨平台差异、与保存冲突；刷新重绑够用。

## 验收与未验

- 自动验证：删除后文件出现在 `.sidelight/trash/`、原路径消失、树刷新、当前文档提示；重名追加随机后缀；跨盘回退路径的 SHA-256 校验；只读/占用失败报错且文件不动。
- UNVERIFIED：真人右键菜单与确认框、Windows 资源管理器里从 trash 恢复、网络盘与 OneDrive 占位文件的移动、超长路径、中文文件名、并发删除同一文件。
