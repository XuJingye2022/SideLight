# 文档真相是编辑器文档树，磁盘 .md 是序列化结果

Sidelight 左侧编辑器基于 Tiptap（ProseMirror）。编辑器内部的文档树是唯一真相，磁盘上的 .md 文件由它序列化产生。保存因此不保证字节级还原：列表符号、表格对齐、强调标记都可能被规范化。

这个代价是主动选的。另一条路是让 Markdown 文本当真相（CodeMirror 6 路线，Obsidian 的做法）：打开什么就原样保存什么，但 Typora 式即时渲染要从零写，表格、代码块、图片、选区映射都靠自己，一个人做按月算。我们选即时渲染与成熟的中文输入法支持，把字节级保真让出去。

三条约束压住损失：

- 未经编辑的文档不写盘，打开不产生保存。
- frontmatter 与解析不了的块原样保留，不转成普通段落。
- 往返损失用 7 个真实样本做 golden 测试量化，不靠感觉。

如果发布后保真成为主要投诉，退出方案是 CodeMirror 6，代价是重写整个编辑层。

## 测量结果（2026-11-15）

`npm run roundtrip` 用 7 个真实样本测了一次，当前结果 3 / 7 完全保真，写进 `docs/roundtrip-report.md`（下面两条是当时 6 个样本的历史记录）：

- 仅 StarterKit：0 / 6 完全保真。
- 补上表格与任务列表：0 / 6 完全保真。表格从「整块丢失」变成「对齐被重排」，任务列表只多一个空行。

三类内容是真的被改坏，不只是重排：YAML frontmatter 被当成标题分隔线、行内 HTML 被转义成 `&lt;div&gt;`、脚注定义被删除而引用被改成行内链接。

所以三条约束里的前两条还没实现。在实现之前，对外不能承诺「打开别人的笔记不会变」。
