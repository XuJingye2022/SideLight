# 质量报告：缺陷与体验问题

检查日期：2026-11-15。检查对象：v0.9.1 浏览器原型。

**修复状态（2026-11-15，v0.10.3）**：22 条全部处理完，每条都在浏览器里复验过。第 14（撤销后建议丢失）、16（源码模式提示/字数/批注）、17（CRLF）、20（超长文档对比）条在 0.10.3 收尾。

方法：一、在无头 Edge 里跑真操作（`scripts/qa.mjs`、`scripts/qa2.mjs`）；二、对 `src/` 做只读代码审查。标「已复现」的是浏览器里真跑出来的，标「代码推断」的是读代码确认但没在界面复现。

## P0 会丢数据

### 1. 切换文档静默丢弃未保存改动（已复现）

打开示例 → 改「开始写.md」→ 点「关于侧灯.md」→ 点回「开始写.md」，改动消失，脏点也没了。在文件树里再点一次当前文件，等于「从磁盘还原」。

预期：切换前给「保存 / 放弃 / 取消」。文件树给有未保存改动的文件加圆点。

### 2. 源码模式下保存，写回的是编辑前的旧正文（已复现）

点「源码」→ 输入新内容 → `Ctrl + S` → 下载到的文件 `含源码改动=false`，长度 243，是旧内容。

原因：保存在源码模式下仍读 `editor.getMarkdown()`，而源码内容只在切回编辑模式时才写回编辑器。

预期：保存、导出、分析共用一个「当前正文」入口，源码模式下就是源码文本。

### 3. 撤销跨文档，把上一篇的正文拉进当前文件（已复现）

打开 A → 打开 B → `Ctrl + Z`：正文变回 A 的内容，标题与保存目标还是 B。

原因：`setContent` 进入撤销栈，载入文档时没清历史。再保存就是把 A 写进 B.md。

### 4. 批注锚点随手动编辑失真，采纳会插错位置（已复现）

分析出两条批注 → 在文首插一句 → 高亮看着没动（装饰器自己映射了位置）→ 鼠标悬停任一批注卡片，重绘后高亮跳到完全无关的文字：从 `主灯是人，侧灯只补光。` 变成 `什么叫侧灯` / `主灯是人`。

`accept` 用的还是旧坐标，会把改写插到别的句子，严重时越界。

预期：批注位置跟着事务走；采纳前用 `quote` 在当前文档重新定位，对不上就不给采纳。

## P1 功能不成立或状态不一致

### 5. 草稿不含脚注，刷新一次再保存会把脚注删掉（代码推断）

`onUpdate` 写草稿只拼了 frontmatter，没拼脚注；恢复时脚注状态为空，`currentMarkdown()` 只留正文引用、丢掉定义。同一路径下公式的 `\\` 也不会被还原。

### 6. 分析流不随文档切换中止，还能并发两条（代码推断）

`abortRef` 只赋值、全文件没有调用 `abort()`；`runAnalysis` 没有 `analyzing` 守卫。切文档或连按 `Ctrl + Enter` 时，结果会落到新文档上，坐标属于旧文档。

### 7. 字号不夹取范围（已复现）

设置里填 999，正文字号真的变 999px；填 0 或清空则正文消失，并被写进本地设置。`Ctrl + ±` 那条路径是夹取的，两条路行为不一致。

### 8. 设置对话框显示旧值，保存会把刚调的字号改回去（已复现）

`Ctrl + =` 两次，正文 18px，打开设置显示 17；点保存后正文变回 17px。组件常驻，`useState(settings)` 只初始化一次。

### 9. 导出 HTML 丢 frontmatter 与脚注（已复现）

导出的 2.1KB 文件里 `title: 周记` 与 `第一条脚注` 都不存在。导出用的是编辑器渲染结果，而元数据与脚注本来就不在编辑器里。

### 10. 查找条跳转后抢焦点，下一个 Enter 会改正文（已复现）

`Ctrl + F` → 输入 → `Enter`：焦点从查找输入框跑到编辑器（`DIV.ProseMirror`），再按 `Enter` 就是在正文里插段落。要连跳必须每次点回输入框。

### 11. 每次按键整篇序列化并写 localStorage，图片撑爆配额后界面冻结（代码推断）

`onUpdate` 里 `getMarkdown()` + `JSON.stringify` + `setItem` 同步执行且无 `try/catch`。不打开文件夹时图片内联成 base64，两三张截图就超过 5MB 配额；`setItem` 抛错后同一回调里的 `setOutline` / `setStats` 永远执行不到，字数与大纲从此不更新。

### 12. 无磁盘句柄的文件保存会静默下载副本（已复现旁证）

示例文件保存不报错、脏点消失，实际内存正文没变；再点文件树就还原。`writeNode` 里那句「无法保存」从界面到不了。

22. 保存对比的文案把所有差异都说成「编辑器规范化」，并把用户自己的改动也算进去；点「取消」只关提示、不阻止后续保存（代码推断）。

## 体验改进建议

1. 顶栏常驻「保存状态 + 目标文件」，示例或无句柄时直接写「只读」，保存成功给一次可见确认。
2. 切换文档前做「保存 / 放弃 / 取消」，文件树给未保存文件加圆点——现在唯一的信号是顶栏一个 4px 的小点。
3. 查找条保持焦点：`Enter` / `Shift + Enter` 连续跳，`Esc` 关闭，替换后不移动焦点。
4. 字号当前值放到状态栏；设置里用步进器，输入时即时夹取。
5. 首次使用把「打开文件夹 / 打开文件 / 试用示例」放到正文区中央；现在入口只占左侧 218px 窄栏，失败原因还落在右侧批注栏。

## 建议的修复顺序

1. 第 1、2、3 条：都是「一个动作就丢数据」，且都在高频路径上。
2. 第 4 条：批注锚点，产品卖点所在，失真比少功能更伤。
3. 第 5、6、7、8、9 条：状态一致性与设置路径。
4. 其余按 P2 排队。

修复本身不是新功能，但会动 `App.tsx` 的主流程；建议一轮只改一类，每轮照旧过门禁与截图。
